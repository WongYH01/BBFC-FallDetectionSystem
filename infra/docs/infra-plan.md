# Cloud infrastructure plan

Status: draft · 2026-10-21 · steps 0–1 done ·
prices and features checked against vendor docs on 2026-10-21

## Goal

Run the whole system on GKE for a short demo, defined as code with OpenTofu
(the open-source Terraform fork; same `.tf` syntax, `tofu` instead of
`terraform`). The cluster is destroyed between demos; the data is not.

| Piece | Runs on |
|---|---|
| `services/notification` (Spring Boot) | GKE |
| `services/detection` (Python, pulls RTSP from the Pi over Tailscale) | GKE |
| Alert records | Cloud SQL (Postgres) |
| Skeleton clips + keypoint files | GCS bucket |
| Images | Artifact Registry `bbfc-registry` (already exists, CI pushes to it) |
| Scheduled retraining | later, [`training-plan.md`](training-plan.md) |

Work through the steps in order: each one only needs what the steps above it
created. Why things are done this way is in [Decisions](#decisions).

## Layout

Two Tofu roots, because they have different lifetimes: `base` holds the data
and lives for the whole project, `cluster` is created and destroyed per demo.

```
infra/
  tofu/
    .gitignore
    base/                  steps 1–4, never destroyed
      versions.tf
      variables.tf
      terraform.tfvars
      .terraform.lock.hcl  generated by `tofu init`, committed
      registry.tf
      network.tf
      iam.tf
      storage.tf
      sql.tf
      secrets.tf
      outputs.tf
    cluster/               steps 5–6, destroyed after each demo
      versions.tf
      base.tf              reads base's outputs
      gke.tf
      iam.tf
      .terraform.lock.hcl
  k8s/                     steps 8–9
    kustomization.yaml
    namespace.yaml
    notification/
      serviceaccount.yaml
      configmap.yaml
      secrets.yaml
      deployment.yaml
      service.yaml
    detection/
      serviceaccount.yaml
      secrets.yaml
      statefulset.yaml
    tailscale/
      egress-service.yaml
```

Training later adds a `training.tf` to each root and `infra/k8s/training/`;
nothing above changes shape for it.

## Step 0 — Prerequisites (by hand, once)

Done in the console or with `gcloud`, run by the developer (never by an AI
session).

1. **Billing.** The project runs on the `$300 / 90-day free trial. While on it
   you **cannot add GPUs** and **cannot request quota increases**. With the
   cluster up this setup costs about $145/month ([Cost](#cost)), so the
   credit lasts about two months of continuous running, far longer if the
   cluster only exists during demos. When the trial ends, every resource is
   stopped and deleted after a 30-day grace period, including Cloud SQL and
   the bucket.
2. **Quotas.** IAM & Admin → Quotas for `asia-southeast1`: 4 vCPUs for the
   node, one in-use external IP, plus Cloud SQL. Trial accounts cannot raise
   them.
3. **APIs.** Enable `container`, `sqladmin`, `servicenetworking`,
   `secretmanager`, `artifactregistry`, `iam`, `iamcredentials`, `sts`,
   `compute`.
4. **State bucket.** Create `<project>-tofu-state` in the region, with object
   versioning on. Tofu cannot create the bucket that holds its own state.
   Both roots use it, under different prefixes.
5. **Tools.** OpenTofu 1.13.x, `gcloud`, `kubectl`, `helm`, `kustomize`
   (or `kubectl kustomize`).

**Done when:** `gcloud storage ls gs://<project>-tofu-state` works.

## Step 1 — `base` skeleton and the existing registry

Creates nothing new in GCP.

**`versions.tf`**
- `terraform { required_version = ">= 1.13" }`.
- `required_providers { google = { source = "hashicorp/google", version = "~> 8.0" } }`.
  OpenTofu resolves `hashicorp/google` from `registry.opentofu.org`.
- `backend "gcs" { bucket = "<project>-tofu-state", prefix = "bbfc/base" }`.
- `provider "google" { project = var.project_id, region = var.region }`.

**`variables.tf`** — `project_id`, `project_number` (for `principal://`
members in step 6), `region` (`asia-southeast1`), `zone`, `clip_bucket_name`.
Each with `description` and `type`.

**`terraform.tfvars`** — the real values. Nothing secret, so it is committed.

**`infra/tofu/.gitignore`** — `.terraform/`, `*.tfstate`, `*.tfstate.backup`,
`crash.log`. Not the lock files, not `terraform.tfvars`.

**`registry.tf`**
- `google_artifact_registry_repository` `bbfc-registry` (Docker), with an
  `import { to = …, id = "projects/<p>/locations/<r>/repositories/bbfc-registry" }`
  block next to it.
- A cleanup policy keeping the 10 most recent versions per image. Not
  optional: every merge to `main` pushes a detection image with torch in it.

**Done when:** `tofu init` succeeds and `tofu plan` shows the import plus the
cleanup policy, and no create or destroy.

## Step 2 — Network

**`network.tf`**
- Custom VPC (`auto_create_subnetworks = false`).
- One subnet in the region with two named secondary ranges, `pods` and
  `services` (VPC-native GKE uses them in step 5).
- Private Service Access for Cloud SQL: a `google_compute_global_address`
  with `purpose = "VPC_PEERING"`, `address_type = "INTERNAL"`, plus
  `google_service_networking_connection` using it. Cloud SQL gets a private
  IP inside the VPC (step 4). The connection itself is free.

No Cloud Router, no Cloud NAT: nodes have their own external IP
([Decisions](#decisions)).

**Done when:** `tofu apply` creates the VPC, subnet and peering.

## Step 3 — Service accounts and project-level roles

**`iam.tf`**

| Identity | Roles |
|---|---|
| `gke-nodes` GSA (node pool) | `roles/container.defaultNodeServiceAccount` on the project; `roles/artifactregistry.reader` on `bbfc-registry` |
| `notification` GSA | `roles/cloudsql.client`, `roles/cloudsql.instanceUser` on the project |

Detection gets no Google service account (see step 6). Grants that name a
Kubernetes ServiceAccount live in the `cluster` root (step 6), because they
belong to the cluster's lifetime.

**Done when:** `tofu apply` creates the two service accounts and the grants.

## Step 4 — Data: bucket, database, secrets

**`storage.tf`**
- The clip bucket (`CLIPS_GCS_BUCKET`): `uniform_bucket_level_access = true`
  (Workload Identity principals cannot use buckets with ACLs),
  `public_access_prevention = "enforced"`, no `force_destroy`. Holds
  `{room_id}/{event_id}.mp4`, `keypoints/incoming/…` and
  `keypoints/labelled/<genuine|false_alarm>/…`.
- `google_storage_bucket_iam_member`: `roles/storage.objectAdmin` for the
  notification GSA, on this bucket only.
- Never a lifecycle rule on `keypoints/labelled/`: that is the training set.
- Workload Identity principals cannot create signed URLs. The app does not
  use them (`GcsClipStore` only writes and moves blobs).

**`sql.tf`**
- `google_sql_database_instance`:
  - `database_version = "POSTGRES_15"`, matching the local
    `supabase/postgres:15` image.
  - `settings.edition = "ENTERPRISE"`, always explicit. Without it the API
    picks `ENTERPRISE_PLUS` for Postgres 16+, which has no shared-core tiers.
  - `tier = "db-f1-micro"` (shared core, about $11/month). It carries no SLA,
    which a demo does not need.
  - Private IP only:
    `ip_configuration { ipv4_enabled = false, private_network = <vpc id> }`.
    A public IP would add $7.30/month.
  - `database_flags { name = "cloudsql.iam_authentication", value = "on" }`.
  - Automated backups on, `deletion_protection = true`.
  - `depends_on` the service networking connection from step 2.
- No `google_sql_database`: every Cloud SQL Postgres instance already has a
  `postgres` database, and creating it again fails. Flyway creates the
  `alerts` schema itself (`spring.flyway.create-schemas=true`).
- `google_sql_user` with `type = "CLOUD_IAM_SERVICE_ACCOUNT"` and
  `name = "notification@<project>.iam"` (the GSA email minus
  `.gserviceaccount.com`). The app has no password user; the only database
  password is the built-in `postgres` one, set by hand below.

**`secrets.tf`** — `google_secret_manager_secret` shells with
`replication { auto {} }`, and **no** `google_secret_manager_secret_version`
(that would put the value in Tofu state):
- `telegram-bot-token`
- `detection-stream-password`
- `tailscale-operator-oauth` (client id + secret for the operator, step 7)

**By hand after apply** (Cloud console):
1. **Secret values.** Secret Manager → the secret → **+ New version** → paste
   the value → **Add new version**. No trailing newline or space.
   `telegram-bot-token` (BotFather) and `detection-stream-password` (MediaMTX
   RTSP) now; `tailscale-operator-oauth` in step 7.
2. **`postgres` password.** SQL → the instance (wait for RUNNABLE) →
   **Users** → `postgres` → ⋮ → **Change password**. The instance is created
   without one, and you cannot sign in until it is set. Nothing else uses it;
   keep it in a password manager.
3. **Schema grant.** Flyway runs `CREATE SCHEMA alerts` as the IAM user, which
   starts with no database privileges, and `CREATE SCHEMA` needs `CREATE` on
   the database. SQL → the instance → **Cloud SQL Studio**, sign in to
   database `postgres` as `postgres` (built-in database authentication), run:
   ```sql
   GRANT CREATE ON DATABASE postgres TO "notification@<project>.iam";
   SELECT has_database_privilege('notification@<project>.iam', 'postgres', 'CREATE');
   ```
   The `SELECT` returns `t`. Only needed before step 8; the grant lives in the
   database, so it survives cluster teardown.
   - If Studio cannot reach the instance (private IP only), run the `GRANT`
     after step 5 from a throwaway pod instead:
     `kubectl run psql --rm -it --restart=Never --image=postgres:15 -- psql "host=<private ip> dbname=postgres user=postgres sslmode=require"`.
     `gcloud sql connect` does not work from a laptop: its `--private-ip`
     still needs a route into the VPC.
   - If the `GRANT` fails with `permission denied`, `postgres` does not own
     the database (see [Unverified](#unverified)).

**`outputs.tf`** — everything `cluster` and the manifests need:
`project_id`, `project_number`, `region`, `zone`, `network`, `subnetwork`,
`sql_connection_name` (`project:region:instance`), `clip_bucket_name`,
`notification_gsa_email`, `gke_nodes_gsa_email`.

**Done when:** the instance is `RUNNABLE`, the bucket exists,
`telegram-bot-token` and `detection-stream-password` each have one version,
and the `SELECT` above returns `t`.

## Step 5 — `cluster` root: GKE

**`versions.tf`** — as in step 1, with
`backend "gcs" { bucket = "<project>-tofu-state", prefix = "bbfc/cluster" }`.

**`base.tf`** — `data "terraform_remote_state" "base"` reading the `bbfc/base`
prefix. Every project, network and identity value comes from its outputs, so
this root needs no `terraform.tfvars`.

**`gke.tf`**

`google_container_cluster`:
- `location = <zone>` (zonal: covered by the GKE free tier),
  `remove_default_node_pool = true`, `initial_node_count = 1`.
- `network` / `subnetwork` from base;
  `ip_allocation_policy { cluster_secondary_range_name = "pods", services_secondary_range_name = "services" }`.
- `release_channel { channel = "REGULAR" }`.
- `workload_identity_config { workload_pool = "<project>.svc.id.goog" }`.
- `secret_sync_config { enabled = true }` — syncs Secret Manager into
  Kubernetes Secrets (GA, GKE 1.33+).
- `control_plane_endpoints_config { dns_endpoint_config { allow_external_traffic = true } }`
  — the DNS-based control plane endpoint, gated by IAM, so laptops need no
  authorized-networks list.
- `maintenance_policy` with a nightly `recurring_window`, so a node
  auto-upgrade does not restart both services mid-demo.
- `deletion_protection = false`: this root exists to be destroyed.

`google_container_node_pool`:
- One pool, `node_count = 1`, `machine_type = "e2-standard-4"`.
- On-demand, the default: do **not** set `spot = true`. A reclaimed Spot node
  stops detection, and falls in that window are missed.
- `disk_size_gb = 50` (the default is 100).
- `service_account` = the `gke-nodes` GSA from step 3, with the
  `cloud-platform` scope.
- `workload_metadata_config { mode = "GKE_METADATA" }`.
- No `ignore_changes` on `node_config`; fix drift instead of hiding it.

**Done when:**
`gcloud container clusters get-credentials <cluster> --zone <zone> --dns-endpoint`
then `kubectl get nodes` shows one `Ready` node.

## Step 6 — Workload IAM (Kubernetes ServiceAccount → Google Cloud)

Needs the cluster's workload identity pool. Two kinds of member:

- **KSA principal** — Google's current recommended form, no GSA involved:
  `principal://iam.googleapis.com/projects/<project_number>/locations/global/workloadIdentityPools/<project>.svc.id.goog/subject/ns/bbfc/sa/<ksa>`
- **GSA impersonation** — the KSA gets `roles/iam.workloadIdentityUser` on a
  GSA (member `serviceAccount:<project>.svc.id.goog[bbfc/<ksa>]`), and the KSA
  carries the annotation `iam.gke.io/gcp-service-account: <gsa email>`.

**`cluster/iam.tf`**

| Member | Kind | Grant |
|---|---|---|
| KSA `bbfc/notification` | GSA impersonation | `roles/iam.workloadIdentityUser` on the `notification` GSA |
| KSA `bbfc/notification` | KSA principal | `roles/secretmanager.secretAccessor` on `telegram-bot-token` |
| KSA `bbfc/detection` | KSA principal | `roles/secretmanager.secretAccessor` on `detection-stream-password` |

Why notification keeps a GSA: a Cloud SQL IAM database login must be named
after a service account email, and a KSA principal has no email.

**Done when:** `tofu apply` is clean and `tofu plan` shows no changes.

## Step 7 — Tailscale operator (by hand)

The Pi's MediaMTX is only reachable on the tailnet. The operator joins the
cluster to it, and step 9's egress Service reaches the Pi through it.
Tailscale's [GCP reference architecture](https://tailscale.com/docs/reference/reference-architectures/gcp)
recommends the operator for GKE; the install follows
[Install the Kubernetes Operator](https://tailscale.com/docs/kubernetes-operator/install-operator).
Not managed by Tofu or by `infra/k8s/`.

**Once** (survives cluster rebuilds):
1. **Tailnet policy.** Admin console → Access controls
   ([grants syntax](https://tailscale.com/docs/reference/syntax/grants)).
   Tag the Pi `tag:pi`, then add:
   ```json
   "tagOwners": {
     "tag:k8s-operator": [],
     "tag:k8s": ["tag:k8s-operator"],
   },
   "grants": [
     {"src": ["tag:k8s"], "dst": ["tag:pi"], "ip": ["tcp:8554"]},
   ],
   ```
   The operator tags itself `tag:k8s-operator` and its proxies `tag:k8s`.
   Without the grant the proxy comes up and RTSP times out. Grants only add
   access: if the default allow-all grant is still there, this one restricts
   nothing.
2. **OAuth client** ([OAuth clients](https://tailscale.com/docs/features/oauth-clients)).
   [Trust credentials](https://console.tailscale.com/admin/settings/trust-credentials)
   → **Credential** → **OAuth**. Write on **General → Services**,
   **Devices → Core** and **Keys → Auth Keys**, each with tag
   `tag:k8s-operator` → **Generate credential**. The secret is shown once;
   use the copy buttons. OAuth client secrets do not expire.
3. **Store it.** Secret Manager → `tailscale-operator-oauth` (step 4 created
   it; do not create another) → **+ New version**, the value on one line:
   ```json
   {"client_id":"<client ID>","client_secret":"tskey-client-..."}
   ```

**Per cluster**, after every `tofu apply` in `cluster` (PowerShell, as run;
`helm repo add` only once per machine):
```powershell
gcloud container clusters get-credentials bbfc --zone <zone> --dns-endpoint
helm repo add tailscale https://pkgs.tailscale.com/helmcharts
helm repo update
$o = (gcloud secrets versions access latest --secret=tailscale-operator-oauth --project <project>) -join "" | ConvertFrom-Json
helm upgrade --install tailscale-operator tailscale/tailscale-operator `
  --version 1.104.2 `
  --namespace tailscale --create-namespace `
  --set-string "oauth.clientId=$($o.client_id)" `
  --set-string "oauth.clientSecret=$($o.client_secret)" `
  --wait
Remove-Variable o
```
The keys are in the chart's
[`values.yaml`](https://github.com/tailscale/tailscale/blob/v1.104.2/cmd/k8s-operator/deploy/chart/values.yaml).

**If the pod crash-loops:** `kubectl -n tailscale logs deploy/operator`.
`oauth2: cannot fetch token: 401 Unauthorized` means Tailscale rejects the
client ID and secret: the client was revoked, or the secret was copied wrong.
Create a new client, add it as a new secret version, rerun the block above,
then `kubectl -n tailscale rollout restart deploy/operator`. More in
[Troubleshooting](https://tailscale.com/docs/kubernetes-operator/reference/troubleshooting).

**Done when:** `kubectl -n tailscale get pods` shows the operator `1/1
Running`, and [Machines](https://console.tailscale.com/admin/machines) shows
`tailscale-operator` tagged `tag:k8s-operator`.

## Step 8 — Notification on the cluster

**`kustomization.yaml`**
- `namespace: bbfc`, lists every manifest as `resources`.
- `images:` maps `notification` (and later `detection`) to
  `<region>-docker.pkg.dev/<project>/bbfc-registry/<service>`, pinned by
  digest (step 10).
- No `secretGenerator` for real secrets — that would commit them.

**`namespace.yaml`** — namespace `bbfc`.

**`notification/serviceaccount.yaml`** — KSA `notification` with
`iam.gke.io/gcp-service-account: <notification_gsa_email>`.

**`notification/configmap.yaml`** — the non-secret half of today's
`.env.cloud`:
- `SPRING_DATASOURCE_URL` — keeps the Cloud SQL JDBC socket factory the app
  already uses (`postgres-socket-factory` in `pom.xml`), so no proxy sidecar:
  `jdbc:postgresql:///postgres?currentSchema=alerts&cloudSqlInstance=<sql_connection_name>&socketFactory=com.google.cloud.sql.postgres.SocketFactory&ipTypes=PRIVATE&enableIamAuth=true`.
  Without `ipTypes=PRIVATE` the connector tries the public IP first, and the
  instance has none.
- `DB_USERNAME=notification@<project>.iam`
- `POSTGRES_PASSWORD=unused` — ignored with IAM login, but the JDBC driver
  rejects an empty password and `application.properties` has no default.
- `CLIPS_STORE=gcs`, `CLIPS_GCS_BUCKET=<clip_bucket_name>`,
  `CLIPS_ENSURE_BUCKET=false`
- `TELEGRAM_CHAT_GROUP_ID`
- `SUPABASE_SERVICE_KEY=unused` — no default in `application.properties`.
- `JAVA_OPTS=-XX:MaxRAMPercentage=75` — under a memory limit the JVM
  otherwise takes only 25% of it as heap.

Dropped from `.env.cloud`: `GCLOUD_ADC_PATH`, `GOOGLE_APPLICATION_CREDENTIALS`
and the `/creds.json` mount (Workload Identity replaces them), `DB_PORT`,
`STORAGE_PORT`, the other `SUPABASE_*` keys. `config/application.yml` is
baked into the image.

**`notification/secrets.yaml`**
- `SecretProviderClass` (`secrets-store.csi.x-k8s.io/v1`, `provider: gke`)
  with `resourceName: projects/<project>/secrets/telegram-bot-token/versions/latest`.
- `SecretSync` (`secret-sync.gke.io/v1`), `serviceAccountName: notification`,
  producing a Kubernetes Secret with key `TELEGRAM_BOT_TOKEN`.

**`notification/deployment.yaml`**
- **`replicas: 1` and `strategy: Recreate`. Never scale it.** Telegram long
  polling (`LongPollingUpdateSource`) and `EscalationScheduler` assume one
  instance: a second pod gets 409 Conflict from `getUpdates` and escalates
  every alert twice. `Recreate` stops the old pod before the new one starts.
  A restart loses nothing: alert state is in Postgres and Telegram redelivers
  unconfirmed button taps for 24 h.
- `serviceAccountName: notification`.
- `envFrom` the ConfigMap and the synced Secret.
- Port 8081. A `startupProbe` on `/api/v1/notification/health` (Flyway runs
  before the app answers), then readiness and liveness on the same path.
- Requests ~250m CPU / 512Mi, plus a memory limit.

**`notification/service.yaml`** — `ClusterIP` service `notification` on 8081.
No LoadBalancer: only detection calls it, and Telegram is polled outbound.

**Apply:** step 10.

**Done when:** the pod is `Ready`, its log shows Flyway migrating `alerts`,
and `kubectl port-forward svc/notification 8081` →
`/api/v1/notification/health` answers.

## Step 9 — Detection on the cluster

**Before writing the manifest:** pin the image user's UID in
`services/detection/Dockerfile` (`useradd -r -u 10001 …`). A PVC mounts
root-owned; compose's named volumes copied ownership from the image, a PVC
does not. With a fixed UID the StatefulSet can set `fsGroup: 10001` and the
non-root app can write its spool.

**`tailscale/egress-service.yaml`** — an `ExternalName` Service `pi-mediamtx`
(`externalName: placeholder`; the operator rewrites it) with
`tailscale.com/tailnet-fqdn: <pi>.<tailnet>.ts.net`. The FQDN follows the Pi
if its tailnet IP changes. (The raw-IP form is `tailscale.com/tailnet-ip`;
one docs page says `tailnet-target-ip`, the operator source does not.)

**`detection/serviceaccount.yaml`** — KSA `detection`, no annotation.

**`detection/secrets.yaml`** — `SecretProviderClass` + `SecretSync` for
`detection-stream-password`, producing key `STREAM_PASSWORD`.

**`detection/statefulset.yaml`**
- `replicas: 1` — one instance per room/camera. A second room is a second
  StatefulSet with its own `ROOM_ID`. A StatefulSet guarantees there are
  never two pods for the room, even while a node is lost.
- One `volumeClaimTemplates` entry (`data`, 5 Gi), mounted twice with
  `subPath`: `outbox` at `/data/outbox` (`SPOOL_DIR`) and `clips` at
  `/app/v2/fall_clips`. Both must survive a restart: the outbox holds alerts
  notification has not accepted yet, and it refers to clip files by path —
  a missing file means the clip is dropped (`service/outbox.py`).
- `securityContext: { runAsUser: 10001, fsGroup: 10001 }`.
- Env: `ROOM_ID`, `ROOM_NAME`, `SERVICE_UI_HOST=0.0.0.0`,
  `SPOOL_DIR=/data/outbox`,
  `NOTIFICATION_BASE_URL=http://notification:8081/api/v1/notification`,
  `MEDIAMTX_HOST=pi-mediamtx`, `MEDIAMTX_RTSP_PORT`, `STREAM_USERNAME`,
  `STREAM_PATH`, `ALLOW_MANUAL_RECORDING=0`, `FALL_CLIPS_ENABLED=1`,
  `FALL_WEIGHTS_TOKEN=""` (weights are baked in at build time);
  `STREAM_PASSWORD` from the synced Secret.
- CPU request 1 vCPU to start. The 23 ms/frame figure in `v2/README.md` was
  measured on a desktop CPU; check `fps` on `/stream/status` and adjust.
- No Service: the UI on 5005 has no auth. Use `kubectl port-forward`.

**Done when:** `kubectl port-forward pod/detection-0 5005` → `/stream/status`
shows frames arriving.

## Step 10 — Deploy (by hand)

CI already builds and pushes `:<sha>` and `:latest` on every merge to `main`,
but only for the service that changed. So deploy the digest each service's
`:latest` currently points to:

```
REG=<region>-docker.pkg.dev/<project>/bbfc-registry
for s in notification detection; do
  d=$(gcloud artifacts docker images describe "$REG/$s:latest" --format='value(image_summary.digest)')
  (cd infra/k8s && kustomize edit set image "$s=$REG/$s@$d")
done
kubectl apply -k infra/k8s
kubectl -n bbfc rollout status deploy/notification
kubectl -n bbfc rollout status sts/detection
```

A digest is reproducible and makes `kubectl rollout undo` meaningful;
commit the updated `kustomization.yaml` so git records what ran.

**Done when:** both workloads run the digests in `kustomization.yaml`.

2. The alert reaches Telegram, with the clip.
3. The clip is in the bucket under `{room_id}/{event_id}.mp4`.
4. The row is in Cloud SQL `alerts`.
5. Triage it in Telegram; the alert row records the outcome.
6. *(Pending: detection does not upload keypoint files yet; once it does,

## Step 12 — Between demos

**Tear down:**
1. Check `/stream/status` and the detection log: the outbox has nothing
   pending. The PVC is deleted with the cluster.
2. `kubectl -n bbfc delete svc pi-mediamtx` while the operator still runs.
   The Service carries the operator's finalizer, so the operator deletes the
   egress proxy's machine from the tailnet before the Service goes. Destroy
   the cluster first and that machine stays behind.
3. `tofu destroy` in `infra/tofu/cluster`.
4. [Remove](https://tailscale.com/docs/features/access-control/device-management/how-to/remove)
   the offline `tailscale-operator` machine on
   [Machines](https://console.tailscale.com/admin/machines). The operator
   never logs itself out (`helm uninstall` does not remove it either), and its
   state Secret dies with the cluster: left there, the next install registers
   as `tailscale-operator-1`.
5. Optional: `gcloud sql instances patch <instance> --activation-policy=NEVER`
   stops Cloud SQL; only its storage is billed. `ALWAYS` starts it again.

**Bring up:** `tofu apply` in `infra/tofu/cluster`, then step 7's per-cluster
block, then steps 10 and 11.

## Decisions

- **One environment, two roots.** No `envs/`, no `modules/`, no Kustomize
  overlays. The split into `base` and `cluster` follows lifetime, not
  environment: a cluster that is destroyed per demo cannot share a root with
  the database (`tofu destroy -target` is discouraged for routine use).
- **GKE Standard, not Autopilot.** Tailscale states the operator "is not
  officially supported on platforms that restrict privileged pods, such as
  GKE Autopilot". Standard also keeps every training option open
  ([`training-plan.md`](training-plan.md)).
- **Zonal, not regional.** Both workloads are single-replica by design, and
  the GKE free tier covers one zonal cluster's management fee.
- **On-demand e2-standard-4, not Spot.** Spot E2 is only ~40% cheaper right
  now, and a reclaimed node blinds detection. The 4 vCPUs leave room for
  a training job later.
- **Public node IPs, no Cloud NAT.** The RTSP feed is ~650 GB/month; Cloud NAT
  bills $0.045/GB in both directions (~$29/month) against $3.65/month for the
  node's IP. Inbound traffic stays blocked by the default firewall, and
  Tailscale gets a direct connection more easily.
- **Workload Identity Federation for GKE, no keys.** Roles go directly to
  Kubernetes ServiceAccounts as `principal://` members, except notification's
  database login (step 6).
- **Dedicated node service account**, not the Compute Engine default one.
- **Tofu owns GCP resources, not Kubernetes objects.** Manifests live in
  `infra/k8s/` and go through `kubectl apply -k`.
- **Secrets: Secret Manager → GKE secret sync → Kubernetes Secret → env var.**
  Both apps read env vars, not files. Values never enter Tofu state, and a
  recreated cluster gets them back without anyone retyping them.
- **Deploy by hand, by digest.** A CI deploy job would fail whenever the
  cluster is destroyed, and CI builds only the changed service's image.

## Not done, on purpose

- `modules/`, `envs/`, Kustomize `base/` + `overlays/` — one environment.
- CI deploy job, Argo CD — the cluster is not always there (step 10).
- Cloud NAT, private nodes — see [Decisions](#decisions).
- Public ingress / LoadBalancer — nothing needs to be reachable from outside.
- A bootstrap Tofu config for the state bucket — created once by hand.
- External Secrets Operator — GKE's built-in secret sync covers it.
- `database_roles = ["cloudsqlsuperuser"]` on the notification SQL user —
  it would remove the manual `GRANT` (step 4), but gives the app admin rights
  on the instance.
- Anything for training — [`training-plan.md`](training-plan.md).
